1. Métricas Clave de Continuidad de Negocio

⏱️ RPO (Recovery Point Objective)

Pérdida máxima de datos aceptable medida en tiempo. Establecido en < 15 minutos para Agropacayales S.A.C., garantizado por copias de logs transaccionales y respaldos programados.

⚡ RTO (Recovery Time Objective)

Tiempo máximo tolerable para recuperar la operatividad completa de la base de datos. Fijado en < 30 minutos mediante procedimientos estandarizados de restauración con reemplazo.

2. Demostración en SQL Server Management Studio (SSMS)

Paso 1: Elaboración del Backup Completo (Full)
  1. En el Explorador de Objetos de SSMS, clic derecho en agropacayales_db ➔ Tasks ➔ Back Up...
  2. Tipo de Backup: Full. Destino: Disk ➔ Ruta: C:\Backups\agropacayales_db_full.bak.
  3. En Backup Options, marcar Verify backup when finished para validar el checksum.
  4. Clic en OK. El archivo se consolida con compresión y verificación.

Script T-SQL Automatizado:

BACKUP DATABASE [agropacayales_db]
TO DISK = N'C:\Backups\agropacayales_db_full.bak'
WITH FORMAT, INIT, NAME = N'agropacayales_db - Backup Completo', 
     COMPRESSION, STATS = 10, CHECKSUM;
Paso 2: Simulación de Contingencia / Pérdida Accidental
USE agropacayales_db;
-- Simulamos una actualización destructiva accidental
UPDATE dbo.cultivos 
SET nombre = 'ERROR_HUMANO_CORRUPTO', observaciones = 'Fallo operativo'
WHERE id_cultivo IN (1, 2, 3);

-- Comprobamos que el dato está alterado
SELECT TOP 3 id_cultivo, id_parcela, nombre, tipo_cultivo FROM dbo.cultivos;
Paso 3: Restauración de la Base de Datos (Restore Database)
  1. Clic derecho en Databases ➔ Restore Database...
  2. Seleccionar Device ➔ Agregar archivo C:\Backups\agropacayales_db_full.bak.
  3. En la pestaña Options:
    • Marcar Overwrite the existing database (WITH REPLACE).
    • Marcar Close existing connections to destination database.
  4. Clic en OK. Base de datos restaurada al 100%.

Script T-SQL de Restauración con Reemplazo:

USE master;
ALTER DATABASE [agropacayales_db] SET SINGLE_USER WITH ROLLBACK IMMEDIATE;

RESTORE DATABASE [agropacayales_db]
FROM DISK = N'C:\Backups\agropacayales_db_full.bak'
WITH FILE = 1, REPLACE, STATS = 10, RECOVERY;

ALTER DATABASE [agropacayales_db] SET MULTI_USER;

3. Demostración en MongoDB Compass (No Relacional)

Paso 1: Exportación / Backup de Colección en MongoDB Compass
  1. Conectarse a mongodb://localhost:27017 en MongoDB Compass.
  2. Entrar a la base de datos agropacayales_db ➔ Colección supplies.
  3. En la barra superior, clic en Export Data ➔ Export the full collection.
  4. Formato: JSON ➔ Archivo: C:\Backups\supplies_backup.json ➔ Clic en Export.
Equivalente CLI para Producción:
mongodump --db=agropacayales_db --collection=supplies --out=C:\Backups\mongo_dump
Paso 2: Simulación de Desastre

En MongoDB Compass, dentro de la colección supplies, ejecutar Drop Collection escribiendo el nombre supplies para confirmar. La colección desaparece por completo.

Paso 3: Restauración / Import Data en MongoDB Compass
  1. Crear la colección supplies dentro de agropacayales_db si fue eliminada.
  2. Clic en Add Data ➔ Import JSON or CSV file.
  3. Seleccionar el archivo C:\Backups\supplies_backup.json ➔ Formato: JSON.
  4. Clic en Import. Los documentos e identificadores INS-... se restauran de inmediato.
Equivalente CLI para Producción:
mongorestore --db=agropacayales_db --collection=supplies --drop C:\Backups\mongo_dump\agropacayales_db\supplies.bson

4. Cuadro Comparativo Técnico

Criterio SQL Server (SSMS / .BAK) MongoDB (Compass / JSON / BSON)
Tipo de Archivo Binario monolítico propietario (.bak). Texto estructurado (.json) o binario (.bson).
Nivel de Consistencia Transaccional ACID estricta a nivel de motor. Consistencia por documento; eventual en réplicas.
Point-in-Time Recovery Soporte nativo a segundo exacto vía Transaction Log. Vía reproducción de oplog en replica set.
Granularidad Base de datos completa, diferencial o Filegroups. Por colección individual, filtros o base completa.
Portabilidad Exclusivo para instancias Microsoft SQL Server. Universal (compatible multiplataforma y entre nubes).

5. Estrategia Empresarial 3-2-1

  • 3 Copias de los Datos: 1 primaria de producción + 2 respaldos independientes.
  • 2 Medios Distintos: Discos locales rápidos (SSD/NVMe) + Almacenamiento masivo (NAS/SAN).
  • 1 Copia Externa (Off-site): Almacenamiento en Cloud (AWS S3, Azure Blob o Google Cloud Storage) con políticas de inmutabilidad (Object Lock) contra Ransomware.
